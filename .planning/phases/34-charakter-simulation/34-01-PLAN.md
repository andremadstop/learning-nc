# Phase 34 Plan 01: Charakter-System + Simulation-Integration

## Objective

Enhance the existing Story-RPG with character class difficulty adjustment (already partially wired), class-specific NPC dialog variations, and PBQ simulation integration at scene/epilog transitions.

## Context

- @app/lib/Service/StoryEngineService.php — character_adjustments already read per-choice
- @app/src/components/AbenteuerMode.vue — character selection exists, simulation rendering missing
- @app/src/components/PbqRenderer.vue — expects `question` object with `pbq_subtype` + `pbq_config`
- @app/data/campaigns/grosser_ausfall.json — has simulation fields in scenes

## Tasks

### Task 1: CHAR-01+02 — Verify and enhance class-based difficulty in StoryEngineService
type: auto

StoryEngineService already reads `character_adjustments[class].difficulty_modifier` per choice.
Enhance: also use campaign-level `characters[class].skill_bonus_pools` and `skill_penalty_pools`
to auto-compute a modifier when `character_adjustments` is absent from a choice.

- Bonus pool match: `-1` modifier (easier)
- Penalty pool match: `+1` modifier (harder)
- If per-choice `character_adjustments` is present, it takes precedence

### Task 2: CHAR-03 — Class-specific NPC dialog in campaign JSON + rendering
type: auto

Add support for `npc_dialog.class_text` map in campaign JSON (class-keyed alternate texts).
Update `buildSceneResponse` to inject the class-specific text when available.
Update `grosser_ausfall.json` with 1-2 example class_text entries to demonstrate.

### Task 3: SIM-01+02 — Simulation phase in AbenteuerMode.vue
type: auto

When a scene has `simulation` field (not null), AbenteuerMode.vue must:
1. Show the simulation BEFORE showing choices (or as an inline phase)
2. Import PbqRenderer and render it with a stub PBQ question config
3. Track simulation result (pass score >= 50% = success)
4. Pass simulation result to `showEpilog()` to select correct epilog variant

Add `simulation` phase to the component:
- New `phase = 'simulation'` state
- `simulationResult` data property
- Stub PBQ question config derived from `scene.simulation.type`
- `submitSimulation(answer)` method: score answer, set result, advance to epilog or next scene
- `showEpilog` already accepts `outcome` — pass 'success', 'partial', or 'fail' based on simulation score

### Task 4: Deploy + Verify
type: auto

Build frontend and deploy to learning-dev:
1. `npm run build`
2. rsync + docker cp + opcache reset
3. Verify AbenteuerMode renders simulation phase

## Verification

- [ ] StoryEngineService uses skill_bonus/penalty_pools when character_adjustments absent
- [ ] NPC dialog renders class-specific text when available
- [ ] AbenteuerMode shows PbqRenderer when scene.simulation is not null
- [ ] Epilog outcome reflects simulation result

## Success Criteria

1. Character class influences skill check difficulty — architect gets easier routing questions
2. NPC dialogs can show different text per character class
3. Scenes with simulation field trigger PbqRenderer inline
4. Simulation result (pass/partial/fail) selects correct epilog
