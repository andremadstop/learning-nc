<behavior>
verifyByVerificationId(vid) returns an associative array with a 'status' key and (on found+sig-OK
branches) a public DTO. Test cases (CertificateVerifyServiceTest, reuse SigningServiceTest keypair +
tamper helpers ~lines 39/113):
  - testValid: real signed JWT, key status 'active', kid/issuer.id/id all bound → status 'valid' + DTO
  - testTamperedInvalid: flip one payload byte → SigningService::verify false → 'invalid'
  - testRevokedSigningKeyInvalid (Codex #1): findByKeyId returns a key with status 'revoked' → 'invalid'
      even though the bytes verify (did.json disowns it)
  - testVerifiesAgainstCertKeyNotActiveKey: cert.key_id resolves a 'retired' key; an unrelated 'active'
      key exists; verify uses the retired key and returns 'valid' (mapper called with cert.key_id)
  - testClaimBindingRejectsSubstitution (Codex #2): a credential_json validly signed by the same key
      but whose payload id != 'urn:uuid:'+vid (OR issuer.id != hostDid OR header kid mismatch) → 'invalid'
  - testExpiryPrecedence: fake clock; expires_at < now → 'expired'; expires_at NULL → never expired (valid)
  - testRevokedTombstone: revoked=true → 'withdrawn' + 'revoked_at' present (NOT 404), takes precedence
      over expiry
  - testDtoNoLeak (VERIFY-03): the returned DTO array, serialized, does NOT contain the recipient name
      fixture ("Jürgen Müller"), user_id, key_id, credential_json, or active_idem_key
Status precedence (LOCK this order): not-found → 'unknown'; key unresolved/status==revoked/wrong-length/
  sig-fail/claim-mismatch → 'invalid'; revoked → 'withdrawn'; expires_at!==null && <now → 'expired'; else 'valid'.
</behavior>
