<objective>
AUDIT-08 — Audit-Liveness admin widget: surface checkpoint health at a glance in the existing
Learning admin settings panel (last checkpoint, events since last checkpoint, anchor status, and a
warning when a checkpoint is overdue).

Purpose: Admins should see whether the tamper-evidence system is alive without SSHing in to run
`occ learning:audit:verify`. A silently-stalled checkpoint job is exactly the failure a compliance
auditor cares about, so a missing checkpoint (> expected interval) must produce a visible warning.

CRITICAL ARCHITECTURE NOTE: The Learning admin settings UI is a **Vue component**
(`app/src/components/AdminSettings.vue`, Options API) mounted into `app/templates/settings/admin.php`
(a 143-byte `<div id="learning-admin-settings"></div>` stub). It fetches its data over REST from
`SettingsController::getAdmin()` via `axios.get('/apps/learning/api/settings/admin')`. The PHP
`AdminSettings.php::getForm()` params array is NOT rendered — a server-rendered PHP widget in
`admin.php` would be invisible. This plan therefore extends the REST payload + the Vue component,
NOT `AdminSettings.php` / `admin.php`.

This plan CONSUMES `AuditCheckpointService::getLivenessStatus()` (built in Plan 161-01). It does NOT
redefine that method — it only renders its output.

Output: `getAdmin()` merges the liveness array; `AdminSettings.vue` renders it; a Vitest proves the
overdue banner.
</objective>
