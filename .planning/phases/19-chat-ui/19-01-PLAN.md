# Phase 19 Plan 01: Chat-UI — VirtuProfBubble Freitext-Chat

## Objective

Extend VirtuProfBubble.vue with a full chat interface: text input, scrollable message history (max 20), typing indicator with `talk` animation, and a "Erkläre diese Frage" quick-action that learning modes can trigger after a wrong answer.

## Context

- `app/src/components/VirtuProfBubble.vue` — pure display component, receives props from VirtuProf.vue
- `app/src/components/VirtuProf.vue` — stateful parent, handles all API calls, emits/listens to `$root` events
- `app/src/components/VirtuProfAvatar.vue` — has `animation` prop; `talk` animation = nodding (already exists)
- Backend endpoint: `POST /api/virtu-prof/chat` — accepts `{message, poolId?, courseId?, questionId?}`, returns `{answer, fallback}`
- `app/src/utils/virtuprof-i18n.js` — `translateVirtuProf(lang, key)` for multilingual strings
- VirtuProf.vue passes `language` and a `step` object to VirtuProfBubble; bubble emits `action` events up

## Architecture Decision

Chat state lives in **VirtuProf.vue** (not VirtuProfBubble) to keep the bubble as a pure display component and maintain session history across bubble open/close cycles. VirtuProfBubble receives `chatMessages`, `chatLoading` as props and emits `chat-send` event with the user message.

## Tasks

### Task 1: Add chat props + input UI to VirtuProfBubble.vue
**type**: auto
**files**: `app/src/components/VirtuProfBubble.vue`

Add to VirtuProfBubble:
- Props: `chatMessages` (Array, default []), `chatLoading` (Boolean, default false)
- Data: `chatInput` (String, '')
- Template: below the existing `.bubble-actions` area, always render `.chat-section`:
  - `.chat-history` div (scrollable, max-height 240px, overflow-y auto) — render each message as `.chat-msg.chat-msg--user` or `.chat-msg.chat-msg--assistant`
  - Typing indicator: `v-if="chatLoading"` — three pulsing dots `.typing-dot`
  - `.chat-input-row`: `<input>` (v-model chatInput, @keyup.enter sendChat, :disabled chatLoading) + send `<button>` (@click sendChat, :disabled chatLoading || !chatInput.trim())
- Method `sendChat()`: if chatInput.trim() emit `chat-send` with chatInput.trim(), clear chatInput
- After new message arrives, scroll `.chat-history` to bottom (use `$nextTick` + ref)
- i18n: use `vt('Ask VirtuProf...')` for placeholder, `vt('Send')` for button
- Style: scoped CSS — user bubble right-aligned (primary color background), assistant bubble left-aligned (background-hover); typing dots pulse animation; `prefers-reduced-motion` guard

**Done when**: VirtuProfBubble renders chat input field and chat history area with correct styling

### Task 2: Wire chat state and API call into VirtuProf.vue
**type**: auto
**files**: `app/src/components/VirtuProf.vue`

Add to VirtuProf.vue:
- Data: `chatMessages` (Array []), `chatLoading` (Boolean false)
- Pass as props to VirtuProfBubble: `:chat-messages="chatMessages"` `:chat-loading="chatLoading"`
- Listen to `@chat-send="handleChatSend"` event from VirtuProfBubble
- Method `handleChatSend(message)`:
  1. Push `{role: 'user', text: message}` to chatMessages
  2. Set chatLoading = true, currentAnimation = 'talk'
  3. Call `axios.post(generateUrl('/apps/learning/api/virtu-prof/chat'), { message, ...this.chatContext })`
  4. On success: push `{role: 'assistant', text: response.data.answer || this.vt('Sorry, no answer available.')}` to chatMessages
  5. On error (400 = input too long/invalid): push `{role: 'assistant', text: this.vt('Your message could not be processed. Please try a shorter question.')}` to chatMessages; on 503: push `{role: 'assistant', text: this.vt('AI is currently disabled. Please contact your admin.')}`; other errors: push generic error message
  6. Trim chatMessages to max 20 entries (oldest removed first)
  7. Set chatLoading = false, restore currentAnimation to 'talk' then back to 'idle' after 1.5s
- Data: `chatContext` (Object {}) — populated via `virtuprof:context` events (pick poolId, courseId from currentContext if available)
- In `clearPresentation()`: also reset chatMessages = [], chatLoading = false
- Make sure bubble is visible when chat is used (open help view if not already open)

**Done when**: Sending a chat message calls the API, appends user + assistant bubbles, shows loading state

### Task 3: Explain-This-Question quick-action (CHAT-05)
**type**: auto
**files**: `app/src/components/VirtuProf.vue`, `app/src/components/TrainingMode.vue`

In VirtuProf.vue:
- Listen to new `$root` event: `virtuprof:explain-question` with payload `{questionText, correctAnswer, poolId?, courseId?}`
- Handler `handleExplainQuestion(payload)`:
  1. Open VirtuProf bubble (set visible=true, isMinimized=false) if not already
  2. Update chatContext with `poolId`/`courseId` from payload
  3. Pre-build message string: `this.vt('Explain this question: {question} — correct answer: {answer}', { question: payload.questionText, answer: payload.correctAnswer })`
  4. Call `handleChatSend(message)` directly
- Register/unregister in mounted/beforeDestroy

In TrainingMode.vue:
- After showing wrong answer feedback (where `answered === true && !wasCorrect`), add a "Erkläre diese Frage" button:
  ```html
  <NcButton type="tertiary" size="small" @click="explainViaVirtuProf">
    {{ t('learning', 'Explain via VirtuProf') }}
  </NcButton>
  ```
- Method `explainViaVirtuProf()`:
  ```js
  this.$root.$emit('virtuprof:explain-question', {
    questionText: this.currentQuestion.question,
    correctAnswer: this.correctAnswerText,
    poolId: this.poolId,
    courseId: this.courseId,
  })
  ```
- Only show button if the question has been answered (not before answer reveal)

**Done when**: Clicking "Explain via VirtuProf" in TrainingMode opens VirtuProf with auto-sent explanation request

### Task 4: i18n + CSS polish + accessibility
**type**: auto
**files**: `app/src/components/VirtuProfBubble.vue`

- Ensure all new string keys are present in translation dict or fall back gracefully via `vt()`
- `prefers-reduced-motion`: typing dots animation should be `opacity: 1` static (no pulse) when reduced motion
- RTL support: chat bubbles should flip correctly with `dir` already set on `.virtuprof-bubble`
- Focus management: after sending, refocus the chat input field (use `$refs.chatInput.focus()`)
- ARIA: `role="log"` on `.chat-history`, `aria-live="polite"` for new messages, `aria-label` on send button
- Keyboard: Enter sends, Shift+Enter would require textarea — keep as single-line input (500 char limit matches backend SEC-01)
- Max length: add `maxlength="500"` to chat input

**Done when**: Accessibility, RTL, and reduced-motion all work correctly; chat input refocused after send
