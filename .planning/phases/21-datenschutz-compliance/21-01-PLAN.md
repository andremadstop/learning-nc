# Phase 21 Plan 01: Datenschutz & Compliance

## Objective

Implement DSGVO compliance for the VirtuProf AI feature: opt-in consent dialog before first chat use, frontend respect for the admin `ai_enabled` toggle (hide chat when disabled), privacy documentation in README.md and info.xml, audit of LLM context for PII, and a Google DPA hint in Admin-Settings.

## Context

- VirtuProfBubble.vue: chat section always visible, `sendChat` emits `chat-send` event to VirtuProf.vue
- VirtuProf.vue: `handleChatSend()` sends to `/api/virtu-prof/chat`; backend returns 503 when ai_enabled=no
- VirtuProfController.php: `chat()` already guards on `ai_enabled=yes`; `getState()` does NOT return ai_enabled
- RagContextService.php: Privacy comment exists, no PII in context (userId used only for DB queries, not returned)
- GeminiService.php: audit log stores userId — this is acceptable (internal audit, not LLM context)
- AdminSettings.vue: shows general settings but NO gemini_api_key or ai_enabled fields yet
- info.xml: no `<privacy>` element
- README.md: no privacy section

## Tasks

### Task 1: PRIV-01 — User opt-in consent dialog

**Files:** `app/src/components/VirtuProf.vue`, `app/src/components/VirtuProfBubble.vue`

**What:** Before the first AI chat message is sent, show a consent dialog: "Deine Frage wird an Google Gemini gesendet. Bist du einverstanden?" with "Zustimmen" and "Abbrechen" buttons. Store consent in `localStorage` key `learning:ai_chat_consent` (value `accepted`). On subsequent opens, skip the dialog if consent already given.

**How:**
1. In `VirtuProf.vue`, add `aiChatConsent` data property (initial: read from localStorage)
2. Add `showAiConsentDialog` data flag
3. In `handleChatSend()`, before sending: if no consent, set `showAiConsentDialog = true`, buffer the pending message in `pendingChatMessage`, return early
4. Add `handleConsentAccept()`: store consent in localStorage, send buffered message, hide dialog
5. Add `handleConsentDecline()`: clear pending message, hide dialog
6. Pass `showAiConsentDialog` prop to VirtuProfBubble, emit `consent-accept` / `consent-decline`
7. In `VirtuProfBubble.vue`, render consent overlay when `showConsentDialog` prop is true

**Done criteria:**
- First chat message triggers dialog
- Accepting sends the message and never shows dialog again (same session + localStorage)
- Declining clears the input, no message sent

### Task 2: PRIV-02 — Frontend hides chat when ai_enabled=no

**Files:** `app/src/components/VirtuProf.vue`, `app/src/components/VirtuProfBubble.vue`

**What:** Load `ai_enabled` from `/api/virtuprof/state` (extend backend response), hide the chat section in VirtuProfBubble when `aiEnabled` is false.

**How:**
1. In `VirtuProfController.php` `getState()`: add `'ai_enabled' => $this->config->getAppValue('learning', 'ai_enabled', 'no') === 'yes'` to response
2. In `VirtuProf.vue` `loadState()`: read `response.data?.ai_enabled` and store in `aiEnabled` data property (default: false)
3. Pass `:ai-enabled="aiEnabled"` prop to VirtuProfBubble
4. In `VirtuProfBubble.vue`: add `aiEnabled` prop (Boolean, default: false), wrap chat-section in `v-if="aiEnabled"`

**Done criteria:**
- When `ai_enabled=no`: chat input invisible
- When `ai_enabled=yes`: chat input shown
- Frontend reflects actual backend state on load

### Task 3: PRIV-03 — Privacy documentation

**Files:** `app/appinfo/info.xml`, `README.md`

**What:** Add privacy section to info.xml and README.md explaining what data is sent to Google Gemini.

**info.xml:** Add `<privacy>` element with external data usage and privacy policy link.

**README.md:** Add "## Privacy & AI" section explaining:
- VirtuProf AI is opt-in (user must consent before first message)
- Admin can disable AI globally
- What is sent to Gemini: question text (max 500 chars), pool questions (sample, max 15, truncated), course name, Leitner box stats (numeric only), last wrong question text
- What is NOT sent: username, email, user ID, passwords, personal data
- Link to Google's privacy policy

**Done criteria:**
- info.xml has `<privacy>` element
- README.md has a "Privacy & AI" section

### Task 4: PRIV-04 — Verify no PII in LLM context

**Files:** `app/lib/Service/RagContextService.php`, `app/lib/Service/GeminiService.php`

**What:** Audit both services and confirm (with a code comment) that no PII flows to the Gemini API. Add a `@privacy-audit` comment to GeminiService::buildSystemPrompt() documenting what IS and is NOT in the context.

**Findings from reading the code:**
- `RagContextService::buildContext()`: userId used for DB queries, never returned in array. Returns: pool_name, pool_questions (question text + answers), leitner_stats (numeric), course_name, last_wrong (question text + answer text). No userId, email, or display name in output.
- `GeminiService::buildSystemPrompt()`: receives $ragContext array — no PII there. Does NOT include userId or language preference (language from IConfig but not injected into context payload, only used to set response language).
- `GeminiService::writeAuditLog()`: stores userId in DB audit table — this is INTERNAL audit, not sent to Gemini API.

**Action:** Add explicit `@privacy-audit` docblock comments to both services confirming no PII in LLM context.

**Done criteria:**
- Both services have `@privacy-audit` comments
- No userId/email/displayName in `$ragContext` array or system prompt

### Task 5: PRIV-05 — Google DPA hint in Admin-Settings

**Files:** `app/src/components/AdminSettings.vue`

**What:** Add a "VirtuProf KI-Assistent" section to AdminSettings.vue showing:
1. The `ai_enabled` toggle (load from/save to API)
2. The Gemini API Key field (masked input, load gemini_api_key_set boolean)
3. A NcNoteCard info box with: "Wenn die KI aktiviert ist, werden Fragen an Google Gemini gesendet. Bitte stelle sicher, dass du das Google Data Processing Addendum (DPA) akzeptiert hast." + link to DPA

**How:**
1. Extend `form` with `aiEnabled` (boolean) and `geminiApiKey` (string, write-only)
2. In `load()`: read `ai_enabled` and `gemini_api_key_set` from API response, set form values
3. In `save()`: include `ai_enabled` in PUT payload; include `gemini_api_key` only if non-empty
4. Add AI section to template above the Save button with toggle, key input, and DPA NcNoteCard
5. AdminSettings.php already passes `ai_enabled` and `gemini_api_key_set` — extend `SettingsController` or check which controller handles `/api/settings/admin`

**Done criteria:**
- Admin can toggle ai_enabled via UI
- Admin can enter Gemini API key via UI (masked)
- DPA link visible when AI section is visible
